# Stealth RPC: Индекс по версии скрипта

## Контекст
- RPC `get_utxos_by_script_version` уже реализован и возвращает курсор.
- Текущая реализация в `DbUtxoSetByScriptPublicKeyStore::get_utxos_by_script_version` использует последовательный обход всех записей с фильтрацией по `version`.
- Это приемлемо как fallback, но на больших UTXO-сетах будет давать линейное время от общего числа UTXO, а не от количества нужной скрипт-версии.

## Цель
Сделать выборку по `script_version` с помощью «настоящего» индекса, чтобы проходить только по нужным записям.

### Варианты
1. **Префиксные ключи**: расширить ключ `UtxoEntryFullAccessKey`, чтобы `CachedDbAccess::seek_iterator` принимал bucket вида `[version || script_len || script]`, и стартовать итератор сразу на правильном префиксе. Потребуется:
   - Сохранить «сырой» ключ из курсора (сейчас уже передаём `cursor_key`).
   - Передавать bucket с фиксированной частью (`version` + `script_len`) и использовать `seek_iterator(Some(bucket), Some(cursor_key), ...)`.
2. **Отдельный индекс**: завести store `ScriptVersionIndex` с layout `version -> Vec<(ScriptPublicKey, Outpoint)>`. При обновлении UTXO записывать туда же. Дороже по записям, но ещё быстрее по чтению.

### Минимальный план (вариант 1)
1. Реализовать утилиту, которая строит bucket для заданной версии без полного скрипта (например, `[version_le, 0u64]`).
2. В `DbUtxoSetByScriptPublicKeyStore::get_utxos_by_script_version` заменить `iterator()` на `seek_iterator(Some(bucket), ...)`.
3. Настроить курсор так, чтобы он содержал полный key (уже делаем) и при следующем запросе этот key передавался как `seek_from`.
4. Прогнать `cargo check -p kaspa-utxoindex -p kaspa-rpc-service`, сделать интеграционный тест, который проверяет восстановление кошелька с большими данными (можно через mocking).

### Риски / проверки
- Нужно гарантировать, что bucket для версии корректно совпадает с layout, который формирует `ScriptPublicKeyBucket`.
- Проверить, что `cursor_key` всегда непустой (для первого запроса оставлять `None`, иначе restart будет невозможен).
- Не забыть про `limit+1` страницу в RPC (уже сделано) — тесты должны закрыть это вместо ручных проверок.
